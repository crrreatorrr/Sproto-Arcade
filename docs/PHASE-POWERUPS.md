# Phase checkpoints and random items

Death retry starts the current phase with full standard health, empty temporary weapons, fresh hazards, and fresh phase targets. Keyboard R and the result Retry button share that route. A phase-2 checkpoint clear is labeled separately and cannot overwrite a full-run best time: in story mode it is shown as rank C, and only a full run without god mode can set a level's saved best (`story-progress.js` `recordBest`, `runtime/fixtures/story-par.test.js`). Explicit phase practice retains its own records. Legacy checkpoint attempts do not submit a partial encounter as a whole-boss replay to the hub. A phase-2 checkpoint clear still saves locally: `clearLevel()` calls `ArcadeHub.recordLocalClear(level)` for every clear, which records the cleared level and any Sprotos it opens in this browser's save (offline too), and calls `ArcadeHub.reportHubClear(level, god, replay, {checkpoint})` for every clear. For a checkpoint clear that call sends one thing only: on level 1, in a hub session, the `arcade.boss_defeated` event for the Breakwater Coin, without a replay log. A checkpoint clear earns no Tickets on any level and does not push the cloud save; the cloud save picks it up at the next full clear or hub sign-in, when local and cloud saves merge. The knockout screen tells the player this before a phase-2 retry. `runtime/fixtures/hub-clear.test.js` covers both halves (owner decision ARC-DEC-01, 2026-11-09).

`phase-powerups.js` is the shared deterministic item planner. Its separate salted stream does not advance authored attack RNG. It permits at most one heart pickup and one shield pickup per phase attempt. Each receives a different random appearance time and location. A retry creates a new attempt. Actual legacy browser starts record a fresh random seed in the existing replay log; explicit `begin(index,false,1,seed)` reproduces it. Modern starts record `options.pickupAttempt` and each restart advances `world.attempt`, so a fixed displayed gameplay seed still produces new pickup timings on each attempt. Reproducing the same seed, attempt, and phase reproduces the item plan.

When items appear. `create()` takes an optional `span`, the phase's expected length in ticks. With a span the first item is planned at 18 to 40% of it and the second at 58 to 82%; without one the original windows apply (first at ticks 180 to 540, second 150 to 450 ticks later). Both forms draw the same random numbers in the same order, so the kind that comes first and both positions are the same either way. Story mode passes a span: `round(boss.max x 6.2)` for a boss's phase 1 (3,261 to 4,526 now that phase 1 is twice the boss's listed health), 1,400 for phase 2, 7,200 for the chase, 5,000 for the climb and 1,800 for the Codebreak arena (`powerupSpan` in `game.js`). Machine Trials passes none and keeps the original windows.

A planned time is the earliest tick, not a promise. In both modes a due item waits while a barrage is live or while the player is blinking after a hit, and appears on the first tick neither is true (`ready` in `step()`). In story mode a due heart also waits while the player has all five hearts (`hold: {life: true}`); if the player is never hurt in that phase attempt, the heart never appears. The four-second expiry starts when an item appears.

The heart adds one HP, capped at the standard maximum of five. The pickup shield is separate from the X skill. It lasts 600 simulation ticks (10 seconds) after collection or until the first actual hit, whichever comes first. It absorbs an ordinary hit. Required dash/shield fronts and forced mechanics still deal damage unless their own counter succeeds; that actual damage also breaks the pickup shield and shows its impact animation. Both uncollected items expire after 240 simulation ticks (4 seconds) and blink during their final 60 ticks. Expiry never permits another spawn of that type during the phase.

Ground items choose nearby walkable surfaces. Flight items use the movement bounds. Legacy chase/climb item positions track camera motion. Pause advances no simulation ticks. Phase transitions discard all old items and shield effects.

Production item emission is gated by `ArcadePhasePowerups.assetsReady` until accepted custom Higgsfield artwork is enabled. `runtime/fixtures/phase-powerups.test.js` explicitly enables that gate only in a controlled test VM to verify real World collection, health, shield behavior, mandatory gates, retry/phase resets, expiry, determinism and surface placement, and it checks the span windows, the held heart and the readiness wait on the planner itself. `runtime/fixtures/barrage-pickup-goldens.test.js` replays the thirteen story goldens and fails if any item appears during a barrage or any heart appears at five hearts. `runtime/fixtures/checkpoint.test.js` exercises phase-1/phase-2 retries, fresh state, distinct records and actual legacy retry functions. These are automated technical checks, not human playtests.

Open point: the phase-2 span of 1,400 was chosen when phase 2 lasted 27 to 39 s for the golden bot. With phase 2 now at the boss's full listed health it lasts 40 to 73 s, so both items are planned in its first half.
