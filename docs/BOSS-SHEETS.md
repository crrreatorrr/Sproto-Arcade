# Boss phase sheets

`boss-sheets.js` is a presentation adapter shared by Machine Trials (`index.html`) and the story campaign (`legacy.html`). It never changes movement, attack schedules, trajectories, HP, damage, collision rectangles, rewards or random streams. Existing dash/shield markings, target rectangles and warnings remain authoritative.

Each boss uses the corresponding original concept-folder name under `art/generated/bosses/`, with `p1.png`, `p2.png`, `p1-projectiles.png`, and `p2-projectiles.png`. Each phase owns its own projectile atlas; no generic projectile set is shared across phases. All 48 production files are approved and marked `ready:true`. Both games decode a stage’s two boss sheets and two projectile sheets before starting; failed or malformed required art blocks the start with a retry or reload message. Already decoded retries start synchronously. Low-level preview drawing retains its original-art fallback. Each final atlas is paired with source hashes, conversion provenance, and measured numeric geometry.

## Export contract

- Transparent PNG; four equal columns and four equal rows. No title, grid, backdrop or scene.
- Boss row 0: four idle frames. Rows 1–3: three different visible weapons shooting, each ordered anticipation, locked anticipation, muzzle firing, recoil. Generic limb gestures do not satisfy the firing rows. Keep the same silhouette scale, body anchor and clearly visible pilot across frames and phases.
- Projectile rows 0–3: the unique projectiles fired by weapon A, weapon B, weapon C, and the phase’s heavy missile, each with four animation frames. Every boss and phase gets its own source-inspired materials and mechanisms. Match each attack’s visible firing weapon to its projectile row; actual authored bounds preserve differing in-game sizes. Preserve a visible core and readable outline at the game's actual projectile size. Requested projectiles face LEFT (`projectileFacing:'left'`); verify actual orientation before approval and set phase asset `facing:'right'` when needed. The adapter normalizes the verified orientation to the game’s existing right-facing projectile transform. Machine Trials mirrors by velocity; legacy custom shots use an explicit local +X `directionAngle` from velocity; original fallback/player art retains its previous direction/rotation calls. Codebreak corrects its existing local +Y rotation with `directionAngle:-Math.PI/2`, yielding the original shot.angle. An explicit direction disables the adapter’s extra vertical-ray turn to avoid double rotation. Supply extractor `rowBounds` and shared all-row `bounds` on each `manifest[id].projectiles[phaseIndex]` asset. The selected row crop masks its pixels, while one common bounds reference sets every row’s scale and registration, preserving relative weapon sizes. Rays rotate along a vertical hazard’s long axis; very long beams tile the uniformly scaled motif across their full dangerous span.
- No frame may cross its cell border. Export with a stable canvas and anchor. Preserve transparent padding consistently across the sheet rather than cropping each frame independently.

Machine Trials samples live authored warnings and releases. An explicit source schedule derives the immutable encounter cycle from `phaseTick - hazard.age`. Repeated instances of even a single authored attack cycle through weapon A, B and C; its boss animation and projectile use the same pure variant. This changes presentation only: one original attack remains one original attack with identical timing, trajectory, damage and counter rules. Rendering consumes no random values and never changes gameplay fields. In-flight projectiles retain their event variant as time advances.

Modern and legacy variant arithmetic is shared with the numeric collision helper in `sprite-hitboxes.js`, preventing art/collision row drift. Enabled geometry stamps immutable numeric `weaponVariant`/`weaponPhase` at projectile creation; rendering reads those fields first. Disabled mode retains original object fields and uses the browser presentation sidecar.

Legacy uses the existing boss move index for the same three presentation variants. `boss-presentation-hooks.js`, loaded after the game, observes original enemy projectile creation and stores immutable phase/variant/birth-tick metadata in a separate `WeakMap`. The wrapper preserves arguments, `this`, return/throw and every projectile field. It introduces no browser globals into the replay simulation’s extracted combat functions. Thus skipped or repeated renders cannot reassign an old projectile to a newer weapon.

Projectile frames use existing age or the captured event birth tick. Display size comes from authored projectile dimensions. Alpha-union `rowBounds` crop each row consistently. One all-row `bounds` union (derived from the row bounds if omitted) defines common scale and center; row crops retain their offsets within that reference. Ordinary shots contain-fit this shared reference into the authored drawing box. Short rays fit the shared reference width to the long axis to remain readable, so their visible cross-axis core must be reviewed before enabling collision profiles. The phase asset `facing` overrides the manifest default after source-image inspection; the adapter normalizes the verified orientation to existing projectile transforms. Vertical rays turn along the long axis; long beams scale the shared reference height to authored thickness and tile the selected row crop across the entire original dangerous span, clipped to its authored drawing box. Boss cells use uniform scaling and a center/bottom anchor.

Each stage’s vehicle-only draw section uses the atlas only when a valid phase atlas is loaded. Surrounding route drawing, cover, reels, relay charges, pressure pipes and shutter cues keep their original drawing calls. No rectangular clipping hides gameplay markings. Summit vent louvers and scanner-state glints are also retained as mechanical overlays. Original separate pilot art is then suppressed because the new sheet includes that character. Review each cockpit and vehicle rectangle before enabling a sheet; the game never infers the pilot from arbitrary concept pixels.

The legacy rooftop chase has one gameplay phase, so it uses Goldie's P1 sheet. Both Goldie phase sheets are supported by Machine Trials. Legacy Codebreak uses its two existing phases. No additional encounter or phase is introduced by the art adapter.

The complete production set has **24 boss phase sheets and 24 phase projectile sheets**. Halloween2008 is stage04 (`ranch/zephyr` internally): P1 Lantern Harvester and P2 Harvest Express. Both slots are required. Legacy health sections are intensity tiers of an existing phase and do not imply additional art phases.

Run `node qa/boss-sheets.test.cjs`, `node qa/boss-weapon-variants.cjs`, and the repository's `node qa/run-all.mjs .`, then inspect both games in the browser. The variant diagnostic exercises all three firing rows and matching projectile rows in each of the 24 phases over 2400 real phase updates, with controlled route eligibility and protected target HP; it is not an earned clear. These automated checks cannot establish final animation quality or pilot visibility; those require inspection of generated files at gameplay size.

Run `python3 tools/verify-boss-assets.py --require-complete` and `python3 tools/verify-boss-hitboxes.py --require-complete` before releasing the complete set. It checks every phase slot, enabled file, RGBA2048×2048 layout, sixteen nonempty padded cells, actual alpha-union bounds, projectile row bounds, and conversion provenance. Without `--require-complete`, it reports production progress and still rejects malformed enabled assets. The output includes final PNG hashes; a pending manifest slot cannot pass the release check.

Hitbox geometry is independent of image readiness. The versioned numeric collision table is active for all 48 source-hashed atlases after solid-core overlay review. Projectile cores use stable reviewed rectangles across all four animation poses; 23 phases use the exact shared opaque intersection, while the previously reviewed Morelight P1 cores retain their stable mechanical footprint through charge flicker; full-span defensive fronts retain their authored span. Production and forced-disabled historical replays are checked separately. Warning rectangles and trajectory arrows sample the same numeric collision bounds as combat; artwork anchors and attack origins stay authored.

## Genuine action-source packing

`tools/pack-boss-actions.py spec.json atlas.png` packs sixteen explicitly selected video timestamps from independently generated idle/A/B/C action clips. `tools/pack-boss-action-images.py spec.json atlas.png` instead packs four genuine 2×2 action images. Both use one common crop, nearest-neighbor scale and bottom baseline for all sixteen poses. The image packer rejects identical source frame reuse. Neither tool invents poses or repairs clipped vehicles.

A video row may declare a reviewed clip-wide `sourceTransform:{scale,translate}` to register differently framed source clips; the complete source canvas must remain inside the destination canvas, and the same fixed transform applies to every selected frame of that clip. Original video/frame hashes and transforms are recorded. Free traveling projectile effects may be explicitly separated from boss art, because their flight is rendered by the separate game projectile. Each exclusion must retain the full physical machine and localized firing cue; video exclusions protect native hardware with a prefire alpha silhouette, never copy reference RGB or reconstruct hidden hardware. Conversion metadata records these masks and source timestamps. Inspect the complete sixteen-frame result before enabling it.
